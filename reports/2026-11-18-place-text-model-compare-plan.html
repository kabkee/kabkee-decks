1. 목적

같은 재료·같은 프롬프트로 여러 모델이 장면 설명 → 장면 가이드 → 장소 소개·설명을 쓰게 해서, 품질(사실·사진 판독·한국어)과 비용·시간을 비교하고 1,636곳 전체 실행에 쓸 모델(또는 단계별 조합)을 고른다.

2. 진행 구조 재료는 고정, 쓰는 부분만 모델별로

① 재료 고정조사한 사실·등록 정보·촬영일·사진을 한 번 뽑아 모든 모델에 똑같이
② 장면 단계사진 → 장면 설명 + 장면 가이드 (장면 4개씩)
③ 장소 단계사실 + 자기 장면 가이드 → 소개·설명·둘러보기 포인트
④ 채점자동 지표 + AI 심사 2개(이름 가림·순서 섞음)
⑤ 오빠 투표대표 8장면 + 5곳을 이름 가린 채 고르기
  • 웹 조사는 모델별로 하지 않는다(지금 조사 결과를 고정해서 준다).
  • 기존 «장면 메모»(Claude Haiku 작성)는 주지 않는다 — Claude 에 유리해지고 사진 판독을 비교할 수 없어서.
  • 결과는 DB 에 쓰지 않는다. 운영 데이터와 분리한 실험이다.

5. 사진 전달 모든 모델 동일

  • 장면마다 큐브 면 4장(앞·오른쪽·뒤·왼쪽), 1024×1024, 같은 순서·같은 라벨, base64 로 직접 전달. 한 호출 = 장면 4개 = 사진 16장.
  • 1024 파일은 원본에 이미 있다(시험 5곳 전 장면 확인). 512 는 같은 사진을 줄인 것이라 작은 글씨를 놓치기 쉽다.
  • 천장·바닥 면은 보내지 않는다(사진 1.5배, 정보는 적음).

8. 한계

  • 웹 조사 능력은 비교하지 않는다 — 조사 결과에 틀린 사실이 있으면 모든 모델이 같이 틀린다.
  • 사진은 4방향 1024px 뿐이다. 실제 VR 을 둘러보는 것과 같지 않고, 오래된 촬영본은 원본 화질도 낮다.
  • 5곳·1회 실행이라 몇 점 차이는 우연일 수 있다 — 확실한 격차만 결론으로 쓰고 근소하면 2차 결선으로 확인.
  • AI 심사는 긴 글·자기 제조사 글·앞 순서 글을 좋게 보는 경향이 있다 — 이름 가리기·순서 섞기·2개 심사로 줄이고 오빠 투표로 최종 판단.
  • Claude 는 CLI, 나머지는 API 라 감싸는 층이 다르다. 모델·가격은 예고 없이 바뀔 수 있다(실행 날짜·가격표를 결과에 기록).
