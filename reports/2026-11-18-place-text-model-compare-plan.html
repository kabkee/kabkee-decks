1. 목적 무엇을 알고 싶은가

지금 v3 가이드는 Claude(Sonnet 5.5)가 쓰고 있다. 같은 재료와 같은 프롬프트를 다른 모델에 줬을 때 사진을 얼마나 정확히 읽는지, 근거 없는 내용을 얼마나 덜 지어내는지, 한국어 문장이 얼마나 자연스러운지, 얼마의 비용으로 1,636곳 전체를 돌릴 수 있는지를 비교해서, 전체 생성에 쓸 모델(또는 단계별 조합)을 고른다.

  • 질문 1 · 품질: v3 기준(사실·의미 전달·역할 구분·정보성)에서 어느 모델이 가장 좋은가
  • 질문 2 · 시각: 360° 사진 4방향을 보고 간판 글자·재질·배치를 틀리지 않게 읽는가(지어내지 않는가)
  • 질문 3 · 비용: 품질 대비 가격 — 전체(장면 29,928개 · 장소 1,636곳) 실행 비용 추정
  • 질문 4 · 조합: 장면 단계는 싼 모델, 장소 단계는 비싼 모델처럼 나눠 써도 되는가

2. 진행 구조 재료는 고정하고, 쓰는 부분만 모델별로 바꾼다

① 재료 고정조사한 사실(현재 cs_place_research)·장소 등록 정보·촬영일·큐브 면 사진을 한 번 뽑아 «재료 묶음»으로 얼린다
② 장면 단계장면 4개씩 사진 16장 + 사실 → 장면 설명(사실 묘사 1~2문장)과 장면 가이드를 한 번에
③ 장소 단계사실 + 자기 모델이 쓴 장면 가이드 → 소개(1~3문장) · 설명 · 둘러보기 포인트
④ 자동 점검JSON 성공률 · 금지어·추측·메타 문장 · 분량 · 사실 id 유효성 · 비용·지연
⑤ AI 교차 채점제조사가 다른 심사 모델 2개, 모델 이름을 가린 채(A~L) 장면·장소 단위로 순위·점수
⑥ 오빠 블라인드 투표대표 8장면 + 5곳 장소 글을 이름 가린 채 고르고, 끝나면 공개

🔒 고정하는 것 (모든 모델 동일)

  • 시스템 프롬프트·출력 형식(JSON 스키마) — v3 g1.5 그대로
  • 사진: 장면마다 큐브 면 앞·오른쪽·뒤·왼쪽 4장, 같은 순서·같은 라벨
  • 조사한 사실(신뢰도 A/B/C 표시) — 웹 조사는 모델별로 다시 하지 않는다
  • 장면 묶음(4개씩)·장면 번호·촬영 시점 문구
  • 추론 강도 «중간»(지원하는 모델만) · 최대 출력 8,000 토큰

🔀 모델마다 달라지는 것

  • 장면 설명·장면 가이드·장소 글 전부(②③)
  • ③ 장소 단계는 «자기 모델이 ②에서 쓴 장면 가이드»를 받는다 — 모델별 결과가 처음부터 끝까지 한 줄로 이어지게
  • API 형식(Zen 이 제조사별 형식을 그대로 받음 — 5장 참고)

📌 기존 «장면 메모»(Claude Haiku 가 쓴 것)는 주지 않는다. 주면 Claude 계열에 유리하고, 사진 판독 능력을 비교할 수 없기 때문이다.

3. 시험 장소 10곳은 많다 — 5곳 · 37장면 권장

비용은 문제가 아니다(아래 9장). 병목은 오빠가 읽어야 하는 양이다. 12모델 × 37장면이면 장면 글만 444개라서 전부 사람이 읽을 수는 없다. 그래서 «서로 다른 함정»을 하나씩 가진 5곳으로 줄이고, 사람은 대표 장면만 본다.

5. 프롬프트와 이미지 전달 모든 모델에 «같은 글자»를 보낸다

5-1. 프롬프트 — v3 g1.5 를 그대로 쓰되 두 군데만 바꾼다

  • 장면 단계: 지금의 장면 가이드 지시문(SCENE_SYSTEM) + 공통 지침(COMMON)에, 출력 항목 description(사진에서 보이는 사실만 1~2문장, 지금의 «장면 메모» 역할)을 추가한다. 기존 장면 메모는 주지 않는다.
  • 장소 단계: PLACE_SYSTEM 그대로(소개 1~3문장 · 설명 1,800자 이내 · 둘러보기 포인트 3~5개).
  • 프롬프트 원문은 비교 페이지 «기준» 탭에 그대로 공개하고, 실행 결과 파일에 프롬프트 해시를 남겨 «같은 프롬프트로 돌렸음»을 증명한다.
// 장면 단계 출력 (모든 모델 공통 JSON 스키마)
{ "scenes": [ { "no": 1,
    "description": "사진에서 확인되는 사실 1~2문장 (장면 설명)",
    "guide": "장면 가이드 2~5문장 (대상·의미·특징)",
    "fids": ["f3"],              // 쓴 조사 사실 id
    "review_note": "" } ] }    // 확인 필요 사항
// 장소 단계 출력
{ "introduction": "...", "paragraphs": [{ "text": "...", "fids": [] }],
  "highlights": [{ "scenes": [2,3], "text": "..." }], "review": { "needs_review": false, "reasons": [] } }

5-2. 이미지 — 무엇을, 어떤 순서로

사진 사양

  • 장면마다 큐브 면 4장: 앞(f) → 오른쪽(r) → 뒤(b) → 왼쪽(l), 각 512×512 JPEG (지금 생성기가 쓰는 파일 그대로 · data/captures/_faces/)
  • 한 호출 = 장면 4개 = 사진 16장. 사진마다 바로 앞에 «S3 사진(오른쪽)» 같은 텍스트 라벨
  • 위·아래 면(천장·바닥)은 보내지 않는다(비용 대비 정보가 적다 — 10장 한계 참고)
  • 모든 모델에 base64 인라인으로 보낸다(URL 방식은 제조사마다 외부 URL 접근 정책이 달라 결과가 흔들린다)

메시지 순서 (모든 모델 동일)

  1. 시스템: 공통 지침 + 장면 지시문
  2. 사용자 텍스트: 촬영 시점 · 장소·유형 · 이 장면들에 연결된 조사 사실
  3. S1 머리글(장면 이름·동선) → 사진 4장(라벨 포함)
  4. S2 … S4 같은 방식
  5. 마지막 텍스트: «S1~S4 장면 설명과 가이드를 JSON 으로»

5-3. Zen API 형식별 보내는 법

Zen 은 제조사 원래 형식을 그대로 받는다. 기본 주소 https://opencode.ai/inference/…, 키는 Authorization: Bearer(Anthropic 형식은 x-api-key 도 가능). 실행 스크립트에서는 Vercel AI SDK 의 제조사별 공급자(@ai-sdk/anthropic·openai·google·openai-compatible)를 Zen 주소로 돌려 generateObject 하나로 통일하는 방식을 권장한다.

// Claude·Qwen Plus  → POST /inference/anthropic/v1/messages
{ "model":"claude-fable-5-2", "system":"…", "max_tokens":8000,
  "messages":[{"role":"user","content":[
    {"type":"text","text":"[S1] 대강당\n사진(앞):"},
    {"type":"image","source":{"type":"base64","media_type":"image/jpeg","data":"…"}}, … ]}] }

// GPT·Grok·Muse    → POST /inference/openai/v1/responses
{ "model":"gpt-6.2-sol", "instructions":"…", "reasoning":{"effort":"medium"},
  "text":{"format":{"type":"json_schema","name":"scenes","schema":{…},"strict":true}},
  "input":[{"role":"user","content":[
    {"type":"input_text","text":"[S1] 대강당\n사진(앞):"},
    {"type":"input_image","image_url":"data:image/jpeg;base64,…"}, … ]}] }

// Gemini           → POST /inference/google/v1beta/models/gemini-4-carbon:generateContent
{ "systemInstruction":{"parts":[{"text":"…"}]},
  "generationConfig":{"responseMimeType":"application/json","responseSchema":{…}},
  "contents":[{"role":"user","parts":[{"text":"[S1] 대강당\n사진(앞):"},
    {"inlineData":{"mimeType":"image/jpeg","data":"…"}}, … ]}] }

// Qwen Max·Kimi·Mistral → POST /inference/openai/v1/chat/completions
{ "model":"kimi-k3", "response_format":{"type":"json_schema","json_schema":{…}},
  "messages":[{"role":"system","content":"…"},{"role":"user","content":[
    {"type":"text","text":"[S1] 대강당\n사진(앞):"},
    {"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}, … ]}] }
🧩 JSON 이 깨질 때: 스키마 강제가 안 되는 모델(Claude·Qwen Max·Kimi K2.x 등은 Zen 목록에 structured_output 표시가 없음)은 «JSON 만 출력» 지시 + 관대한 파서(코드 블록·앞뒤 설명 제거) + 1회 재시도. 그래도 실패하면 «실패»로 기록하고 그 모델 점수에 반영한다(실패율 자체가 비교 지표).

6. 실행과 저장 다시 돌려도 이어서 할 수 있게

  • 스크립트: look360_content_studio/scripts/model-compare/ — pack.mjs(재료 묶음 만들기) · run.mjs --models … --places …(생성) · judge.mjs(AI 채점) · page.mjs(비교 페이지 생성)
  • 재료 묶음: data/model-compare/pack-2026-11-xx.json — 장소 5곳의 사실·등록 정보·촬영일·장면 목록 + 사진 경로. 이 파일 해시가 같으면 «같은 재료»
  • 결과: data/model-compare/{run}/{model}/{place}.json — 원문 응답 · 파싱 결과 · 토큰 사용량 · 계산한 비용 · 지연 시간 · 재시도 횟수 · 프롬프트 해시. 이미 있는 파일은 건너뛴다(중단 후 재개)
  • 동시 실행: 제조사별 2개씩(제조사 한도에 걸려도 다른 모델은 계속 돈다)
  • DB 에는 쓰지 않는다 — 글쓰기 도구·운영 데이터와 완전히 분리한 실험이다
  • Zen 키는 기존 opencode 로그인 키를 환경변수로만 읽고, 결과 파일·페이지에 남기지 않는다

10. 이 테스트의 한계 결과를 읽을 때 같이 봐야 할 것

  • 웹 조사는 비교하지 않는다. 모든 모델이 Claude 가 조사한 사실을 그대로 받는다. 조사 결과에 틀린 사실이 있으면 모든 모델이 같이 틀리고, 모델별 «조사 능력»은 이 시험으로 알 수 없다. (필요하면 별도 시험으로 분리 — 웹 검색 도구 지원이 모델마다 달라 같은 조건을 만들기 어렵다)
  • 사진 정보가 제한적이다. 512px 4방향만 보낸다. 천장·바닥·작은 글씨는 어느 모델도 못 읽을 수 있다. 실제 VR 을 둘러보는 것과 같지 않다.
  • 표본이 작다. 5곳·37장면·1회 실행. 몇 점 차이는 우연일 수 있다. 확실한 격차만 결론으로 쓰고, 근소한 차이는 2차 결선(2회 실행)으로 확인한다.
  • AI 심사의 편향. 긴 글·자기 제조사 글·앞에 놓인 글을 좋게 보는 경향이 있다. 이름 가리기·순서 섞기·제조사 다른 2심으로 줄이지만 없앨 수는 없다. 그래서 오빠 투표가 최종이다.
  • 조건이 완전히 같지는 않다. 추론 강도·JSON 강제 방식·이미지 처리 방식이 제조사마다 달라서, «같은 프롬프트»여도 내부 처리는 다르다. 그 차이까지 포함한 «실사용 성능» 비교로 본다.
  • 모델·가격이 바뀐다. Zen 모델은 예고 없이 갱신될 수 있고, Gemini 4 Carbon 은 12/1 에 가격이 2배가 된다. 결과 페이지에 실행 날짜와 그날 가격표를 같이 남긴다.
  • 운영 비용과 다르다. 지금 생성은 Claude 구독(claude -p)이라 토큰 비용이 0 이다. API 모델로 바꾸면 전체 실행에 위 표만큼 실제 돈이 든다.
  • 외부 전송. 장소 사진·조사 사실을 여러 제조사로 보낸다. 모두 이미 공개된 VR·공개 자료지만, 유료 모델의 데이터 보존 정책은 제조사·Zen 정책을 따르므로 실행 전에 한 번 확인한다(무료 모델은 학습 사용 가능성이 있어 제외했다).
