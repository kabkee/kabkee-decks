## 🤖 jev 는 어떤 도구인가 <span class="badge-date">10/29</span>

| 구분 | 내용 |
|---|---|
| 정체 | TypeSafe AI 의 판정 전용 모델 `jev-1.13` · OpenCode Zen 을 기존 키 그대로 사용 |
| 입력 | 판단 근거(`state`) + 질문(`questions`) — 질문 유형은 «예/아니오»(`noul`) 또는 «선택지 2~16개»(`choice`) |
| 출력 | 확률(0~1) 또는 고른 선택지 — **문장이 없으므로 결과를 해석·파싱할 필요가 없음** |
| 비용·속도 | 판정 1회 약 $0.00002(1,000회에 약 2센트) · 1회 약 0.8초 · 동시 호출 가능 |
| 쓰는 법 | 확률을 코드에서 기준선으로 자르고, 0.4~0.6 같은 애매한 구간은 사람에게 넘김 |

> 일반 LLM 은 «답을 문장으로 쓰게 한 뒤 그 문장을 다시 읽어야» 하지만, jev 는 처음부터 숫자로 답합니다.

## ✅ 왜 쓰기 편한가 — 일반 LLM 과 비교 <span class="badge-date">10/29</span>

| 관점 | 일반 LLM(문장 생성) | jev(판정 전용) |
|---|---|---|
| 결과 형식 | 문장 → 다시 파싱 · 형식이 가끔 어긋남 | **확률·선택지 고정 형식** |
| 기준선 조절 | 프롬프트를 고쳐 다시 돌려야 함 | **숫자 기준만 바꾸면 됨**(0.9↑ 자동 · 0.5↓ 제외 등) |
| 비용 | 건당 수백~수천 토큰 | **건당 약 $0.00002** |
| 대량 처리 | 비용·시간 부담으로 표본만 점검 | **전수 점검이 현실적**(2만 건 $0.40) |
| 사람과 협업 | 근거 설명은 풍부 | 애매한 구간만 골라 **사람 검토 대기열**로 |

## 🎬 유튜브 영상 선택 정확도 <span class="badge-date">10/29</span>

사람이 직접 고른 124곡(후보 620개)을 정답으로 놓고 비교했습니다.

| 방식 | 사람과 같은 영상을 1위로 | 정답·오답 구분력(AUC) |
|---|---|---|
| 기존 규칙 점수 | 52% (65곡) | 0.734 |
| jev 단독 | 70% (87곡) | — |
| **규칙 + jev** | **77% (95곡)** | **0.833** |

- 자동 교체 조건 정확도 <span class="hl-blue">67%(3곡 중 2곡) → 100%(4곡 중 4곡)</span>
- 예: IVE «Looks Can Kill» 후보 5개가 규칙 점수로는 모두 92~93점 → jev 는 공식 MV 0.95, 무대 영상 0.05~0.16 으로 구분해 자동 교체

## 🧪 실험 설계 — Bitwarden 항목 폴더 분류 <span class="badge-date">10/29</span>

| 항목 | 내용 |
|---|---|
| 문제 | 비밀번호 관리자(Bitwarden) 항목 **181개**를 폴더 **14개** 중 하나로 분류 |
| 입력 | 항목 이름·유형·도메인만 전달 — **비밀값은 보내지 않음**, 카드 번호 숫자는 가림 |
| 질문 | 항목당 `choice` 질문 1회 · 폴더마다 한 줄 설명을 기준으로 제공 |
| 기준 | Claude(Opus)가 규칙으로 만든 분류와의 일치율 |
| 비교 대상 | jev 클라우드(`jev-1.13`) · jev-9b 로컬(4bit, RTX 3060 12GB) |

> 정답이 하나로 정해지지 않는 항목(예: 통신사 계정이 «개인 계정»인지 «생활»인지)도 있어서, 일치율은 «정확도의 근사치»로 봐야 합니다.

| 계산·개수·날짜 비교, 여러 단계 추론 | 공개 자료가 밝힌 약점 — 이런 판단은 규칙으로 처리 |
| 가사 검증처럼 미묘한 판정 | 맞는 가사도 중앙값 0.73 → weekly 에서는 적용하지 않음 |

> 판단에 필요한 근거만 넣어야 정확합니다. 관계없는 내용이 많으면 정확도가 떨어집니다.
