## 🔒 인증 없이 데이터를 지울 수 있었습니다 <span class="badge-date">9/3~9/4</span> <span class="badge-new">NEW</span>

테스트 장소를 지우려다 <span class="hl-red">오류 원인을 파고든 것</span>이 출발점이었습니다. 로그인 정보를 **전혀 붙이지 않은 요청**이 거부되지 않고 데이터베이스 삭제 명령까지 도달하고 있었습니다.

| 단계 | 발견한 것 |
|---|---|
| ① 최초 발견 | 장소 삭제 경로가 <span class="hl-red">무인증으로 삭제까지 도달</span> — 우연히 걸린 데이터 제약이 막았을 뿐 |
| ② 같은 유형 확인 | 삭제 계열에서 <span class="hl-red">6곳 추가</span> 발견 |
| ③ <span class="hl-green">전수 재점검</span> | 「삭제만 세었다」는 점을 깨닫고 <span class="hl-green">등록·수정 계열 전체</span>를 다시 조사 — <span class="hl-red">33곳</span> 추가 발견 |

> 판정 기준은 **실제 호출 결과**입니다. 정상이라면 「권한 없음(401)」이 돌아와야 하는데, 문제 지점들은 <span class="hl-red">「없는 데이터(404)」·「잘못된 요청(400)」</span>을 돌려주었습니다. 요청이 이미 <span class="hl-red">인증 관문을 통과해 내부 로직까지 들어갔다</span>는 뜻입니다.

## 🚧 지역 주소 체계 5단계 재정비 <span class="badge-date">진행 중</span>

전국 주소를 <span class="hl-blue">광역 → 시 → 구·군 → 읍·면 → 동·리</span> 5단계로 통일하는 작업입니다. 지역 필터·검색·다국어 표기가 모두 이 체계를 기준으로 동작합니다.

| 단계 | 대상 | 상태 |
|---|---|---|
| 규약 확정 | 5단계 체계 정의 | <span class="hl-green">완료</span> (오너 확정) |
| 화면 대응 | 관리자 5단계 표시·별칭 관리 | <span class="hl-green">완료</span> |
